# Built-in Exceptions

In Python, all exceptions must be instances of a class that derives from
[BaseException](base-classes/BaseException/README.md).  In a `try` statement with an `except`
clause that mentions a particular class, that clause also handles any exception
classes derived from that class (but not exception classes from which *it* is
derived).  Two exception classes that are not related via subclassing are never
equivalent, even if they have the same name.

The built-in exceptions listed in this chapter can be generated by the interpreter or
built-in functions.  Except where mentioned, they have an "associated value"
indicating the detailed cause of the error.  This may be a string or a tuple of
several items of information (e.g., an error code and a string explaining the
code).  The associated value is usually passed as arguments to the exception
class's constructor.

User code can raise built-in exceptions.  This can be used to test an exception
handler or to report an error condition "just like" the situation in which the
interpreter raises the same exception; but beware that there is nothing to
prevent user code from raising an inappropriate error.

The built-in exception classes can be subclassed to define new exceptions;
programmers are encouraged to derive new exceptions from the [Exception](base-classes/Exception/README.md)
class or one of its subclasses, and not from [BaseException](base-classes/BaseException/README.md).  More
information on defining exceptions is available in the Python Tutorial under
[User-defined Exceptions](https://docs.python.org/3.15/tutorial/errors.html#tut-userexceptions).

- [Base classes](base-classes/README.md) — The following exceptions are used mostly as base classes for other exceptions.
  - [`BaseException`](base-classes/BaseException/README.md) — The base class for all built-in exceptions.
  - [`Exception`](base-classes/Exception/README.md) — All built-in, non-system-exiting exceptions are derived from this class.
  - [`ArithmeticError`](base-classes/ArithmeticError/README.md) — The base class for those built-in exceptions that are raised for various arithmetic errors: OverflowError, ZeroDivisionError, FloatingPointError.
  - [`BufferError`](base-classes/BufferError/README.md) — Raised when a buffer related operation cannot be performed.
  - [`LookupError`](base-classes/LookupError/README.md) — The base class for the exceptions that are raised when a key or index used on a mapping or sequence is invalid: IndexError, KeyError.
- [Concrete exceptions](concrete-exceptions/README.md) — The following exceptions are the exceptions that are usually raised.
  - [`AssertionError`](concrete-exceptions/AssertionError/README.md) — Raised when an assert statement fails.
  - [`AttributeError`](concrete-exceptions/AttributeError/README.md) — Raised when an attribute reference (see Attribute references) or assignment fails.
  - [`EOFError`](concrete-exceptions/EOFError/README.md) — Raised when the input() function hits an end-of-file condition (EOF) without reading any data.
  - [`FloatingPointError`](concrete-exceptions/FloatingPointError/README.md) — Not currently used.
  - [`GeneratorExit`](concrete-exceptions/GeneratorExit/README.md) — Raised when a generator or coroutine is closed; see generator.close() and coroutine.close().
  - [`ImportError`](concrete-exceptions/ImportError/README.md) — Raised when the import statement has troubles trying to load a module.
  - [`ModuleNotFoundError`](concrete-exceptions/ModuleNotFoundError/README.md) — A subclass of ImportError which is raised by import when a module could not be located.
  - [`ImportCycleError`](concrete-exceptions/ImportCycleError/README.md) — A subclass of ImportError which is raised when a lazy import fails because it (directly or indirectly) tries to import itself.
  - [`IndexError`](concrete-exceptions/IndexError/README.md) — Raised when a sequence subscript is out of range.
  - [`KeyError`](concrete-exceptions/KeyError/README.md) — Raised when a mapping (dictionary) key is not found in the set of existing keys.
  - [`KeyboardInterrupt`](concrete-exceptions/KeyboardInterrupt/README.md) — Raised when the user hits the interrupt key (normally Control-C or Delete).
  - [`MemoryError`](concrete-exceptions/MemoryError/README.md) — Raised when an operation runs out of memory but the situation may still be rescued (by deleting some objects).
  - [`NameError`](concrete-exceptions/NameError/README.md) — Raised when a local or global name is not found.
  - [`NotImplementedError`](concrete-exceptions/NotImplementedError/README.md) — This exception is derived from RuntimeError.
  - [`OSError`](concrete-exceptions/OSError/README.md) — This exception is raised when a system function returns a system-related error, including I/O failures such as "file not found" or "disk full"…
  - [`OverflowError`](concrete-exceptions/OverflowError/README.md) — Raised when the result of an arithmetic operation is too large to be represented.
  - [`PythonFinalizationError`](concrete-exceptions/PythonFinalizationError/README.md) — This exception is derived from RuntimeError.
  - [`RecursionError`](concrete-exceptions/RecursionError/README.md) — This exception is derived from RuntimeError.
  - [`ReferenceError`](concrete-exceptions/ReferenceError/README.md) — This exception is raised when a weak reference proxy, created by the weakref.proxy() function, is used to access an attribute of the referent…

  - [`StopIteration`](concrete-exceptions/StopIteration/README.md) — Raised by built-in function next() and an iterator's __next__() method to signal that there are no further items produced by the iterator.
  - [`StopAsyncIteration`](concrete-exceptions/StopAsyncIteration/README.md) — Must be raised by __anext__() method of an asynchronous iterator object to stop the iteration.
  - [`SyntaxError`](concrete-exceptions/SyntaxError/README.md) — Raised when the parser encounters a syntax error.
  - [`IndentationError`](concrete-exceptions/IndentationError/README.md) — Base class for syntax errors related to incorrect indentation.
  - [`TabError`](concrete-exceptions/TabError/README.md) — Raised when indentation contains an inconsistent use of tabs and spaces.
  - [`SystemError`](concrete-exceptions/SystemError/README.md) — Raised when the interpreter finds an internal error, but the situation does not look so serious to cause it to abandon all hope.
  - [`SystemExit`](concrete-exceptions/SystemExit/README.md) — This exception is raised by the sys.exit() function.
  - [`TypeError`](concrete-exceptions/TypeError/README.md) — Raised when an operation or function is applied to an object of inappropriate type.
  - [`UnboundLocalError`](concrete-exceptions/UnboundLocalError/README.md) — Raised when a reference is made to a local variable in a function or method, but no value has been bound to that variable.
  - [`UnicodeError`](concrete-exceptions/UnicodeError/README.md) — Raised when a Unicode-related encoding or decoding error occurs.
  - [`UnicodeEncodeError`](concrete-exceptions/UnicodeEncodeError/README.md) — Raised when a Unicode-related error occurs during encoding.
  - [`UnicodeDecodeError`](concrete-exceptions/UnicodeDecodeError/README.md) — Raised when a Unicode-related error occurs during decoding.
  - [`UnicodeTranslateError`](concrete-exceptions/UnicodeTranslateError/README.md) — Raised when a Unicode-related error occurs during translating.
  - [`ValueError`](concrete-exceptions/ValueError/README.md) — Raised when an operation or function receives an argument that has the right type but an inappropriate value, and the situation is not described…

  - [`ConnectionError`](concrete-exceptions/ConnectionError/README.md) — A base class for connection-related issues.
